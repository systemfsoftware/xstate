# @systemfsoftware/xstate-test@2.0.0-beta.2

Two property-test campaigns that run concurrently in one process no longer affect each other: each campaign's stubbed actor outcomes and fast-check scheduler now resolve only inside the campaign that created them. Previously, a campaign could resolve outcomes another campaign had queued, and a campaign run with `scheduler: true` leaked its scheduler into campaigns that had scheduling off, so overlapping campaigns could cover states they never reached or run as if they were scheduled.

Add `@systemfsoftware/xstate-test`, model-based and property testing for XState machines, forked from statelyai/xstate's `next` branch at 2146ae26 (MIT). It behaves like upstream's 2.0.0-alpha.1. Under `exactOptionalPropertyTypes`, optional members that can hold `undefined` declare it explicitly. The `effect` peer range is `^4.0.1` (the monorepo catalog had `^4`), so a consumer resolves at least Effect 4.0.1.

The `statistics` option on `propertyTest()` and `testPaths()` now also accepts a callback: `statistics?: boolean | ((report: string) => void | Promise<void>)`. `true` still prints `formatTestStatistics(coverage)` after a passing campaign; a function receives that same string once instead of the print, so a caller can route the report to its own sink. The campaign awaits a callback that returns a promise. If the callback throws or rejects, the campaign fails with that error, after the `sut.complete` hook ran. Leaving the option out reports nothing, as before. `statistics: false` used to print the report as well; it now reports nothing.
